## 一、调色板迁移：Gist 的 shadcn 变量 → HeroUI v3 token

**冲突的本质**：Gist 用 shadcn 约定，变量是 **HSL 三元组**（`--background: 0 0% 100%`，用时 `hsl(var(--background))`）；HeroUI v3 的同名变量是**完整颜色**（`--background: oklch(...)`）。同名不同义，直接共存会互相覆盖 → `hsl(rgb(...))` 非法，声明被丢弃。

**解法**（`src/index.css`）：

1. 删掉 Gist 自己那套调色板定义（`:root` 与 `.dark` 里的 HSL 三元组），只保留布局/动效变量。
2. `@theme` 里的 `--color-*` 全部改成指向 HeroUI token：

   | Gist 语义 | 映射到的 HeroUI token |
   |---|---|
   | background | `--background` |
   | foreground | `--foreground` |
   | card / card-foreground | `--surface` / `--surface-foreground` |
   | popover / -foreground | `--overlay` / `--overlay-foreground` |
   | primary / -foreground | `--accent` / `--accent-foreground` |
   | secondary / muted / accent | `--surface-secondary` |
   | muted-foreground | `--muted` |
   | destructive | `--danger` |
   | border / input | `--border` |
   | ring | `--focus` |

   这样所有既有组件（用的都是 `bg-background`、`text-muted-foreground` 这类 Tailwind 类）**零改动**就换上了 Nextflux 的配色。
3. 全文 `hsl(var(--X))` → `var(--映射后的token)`；带透明度的 `hsl(var(--X) / 0.5)` → `color-mix(in srgb, <token> 50%, transparent)`。

## 二、主题切换：`data-theme` 驱动五套配色

- HeroUI 只认 `.light/.dark/[data-theme=light|dark]`；自定义主题（stone/leaf/nord-dark）由 `src/styles/nextflux-theme.css` 用 `[data-theme=…]` 覆写同一批 token。
- 应用方式（`src/hooks/useTheme.ts`，对齐 Nextflux 的 themeStore）：`class` 承载 light/dark 语义，`data-theme` 承载具体配色 —— `<html class="light" data-theme="stone">`。
- 首屏防闪：`index.html` 里的内联脚本同步读取 `gist-theme` / `gist-light-theme` / `gist-dark-theme`。
- css 层叠依据：HeroUI 的 token 在 `@layer theme`，我们的覆写在 `@layer base`（HeroUI 自己声明的层序 `theme, base, components, utilities` → base 优先级更高），所以能盖住。
- 柔影 token 用 `@utility` 接到 Tailwind：`shadow-nf` / `shadow-nf-md` / `shadow-nf-inner` / `shadow-nf-btn`。

## 三、踩过的坑（会反复遇到）

1. **未分层的全局规则会压过所有 utility**：Gist 原先写了未分层的 `* { border-color: … }`，导致卡片上的 `border-transparent` 完全失效（边框永远显形）；同一类坑还有未分层的 `.safe-area-*`（`padding-top: env(...)`）压掉了布局容器的 `sm:pt-[17px]`，浮层面板上边距死活不生效。**凡是自定义 CSS 类/全局覆盖，一律放进 `@layer base` 或 `@layer components`。** 排查手法：`getComputedStyle(el)` 读实际生效值，再看该规则是否带 layer。
2. **`@import` 必须在文件顶部**：把 `./styles/nextflux-theme.css` 插在 `@plugin` 之后会报错；顺序还决定层叠优先级，要放在 `@import "@heroui/styles"` 之后。
3. **HeroUI v3 装完要补 peer 依赖**：`react-aria`、`react-aria-components`、`@react-aria/ssr`、`@react-aria/i18n`、`@react-aria/utils`（不然运行时报缺依赖）。
4. 项目规定用 bun；本机原先没有 bun，已用 `npm i -g bun` 装上（1.4.2）。
5. **批量替换 CSS 变量后必须目视验证**：把 `hsl(var(--x) / 0.5)` 批量换成 `color-mix(...)` 时漏写 `var()`，生成 `color-mix(in srgb, --overlay 98%, transparent)` 这种**静默无效**的声明（浏览器直接丢弃，不报错）——下拉菜单的玻璃底和阴影当场就是坏的，只有截图才看得出来。改完 CSS 一定要在浏览器里看一眼受影响组件。
6. **TSX 里的 `hsl(var(--x))` 会整体失效**：调色板变量迁走后，组件里残余的 `hsl(var(--background) / 0.98)` 这类任意值全部变成空气（ProfileButton 的下拉菜单中招）。改配色时用 `grep -rn 'hsl(var(--' src` 全仓搜一遍，别只看 CSS。
7. **截图前必须校验页面**：Hermes 的浏览器是共享会话，`ensure_real_tab()` 可能切到别的任务开着的标签页——本次就抓到过一张 Discord 登录页当"效果图"。截图前先 `page_info()` 确认 url 落在 `localhost:5173`，否则 `goto_url()` 重来；改视口用 `cdp('Emulation.setDeviceMetricsOverride', width=1440, height=900, deviceScaleFactor=2)`，否则截图会缩成 890×503。

## ego 浏览器实测踩点（2026-09-16）

- **Radix 的下拉/菜单不认合成 click**：在 `page.evaluate()` 里 `el.click()` 打不开账户菜单，
  要用真实输入——`page.mouse.click(x, y)` 或
  `page.cdp("Input.dispatchMouseEvent", { type: "mousePressed"|"mouseReleased", x, y, button: "left", clickCount: 1 })`。
  侧栏里有两个 `[aria-haspopup=menu]`（排序菜单 + 账户菜单），按坐标或 ref 取，别用「最后一个」。
- **没法用 page.on / 加载前注入**：要挂钩 `fetch`、`IntersectionObserver` 之类，
  得 `page.cdp("Page.enable")` + `page.cdp("Page.addScriptToEvaluateOnNewDocument", { source })` 再 reload；
  加载后再挂钩，已经创建的观察器抓不到。
- **指标要自己可控**：用「未读数」验证滚动已读会误判——视图里多数条目本来就已读，
  滚动变化看不出来。先用 API 把若干条改成未读，再滚动断言差值（本项目就是这么确认两栏社交媒体视图没退化的）。
- **别把测量误差当回归**：换一个已知正常的视图跑同一套检查；那边正常而这边不正常，才是真差异。
- 截图前先确认 URL 落在 localhost:5173（浏览器会话是共享的，可能停在别的标签页）。

## 本地开发的坑：容器会跟源码后端抢 8080（2026-09-16 踩到）

`docker-compose.yml` 里写了 `restart: unless-stopped`，容器被停掉后可能自己起来，OrbStack 又会占住 `0.0.0.0:8080`。
现象：源码后端 `go run` 报 `listen tcp :8080: bind: address already in use` 直接退出，而浏览器里访问到的还是**旧镜像**的接口
（表现为新加的路由 404、新设置字段缺失）。排查与处理：

```bash
lsof -nP -i :8080 -sTCP:LISTEN     # 看到 OrbStack 就是容器占了端口
docker ps -a | grep gist           # 确认容器是不是又 Up 了
docker stop gist-nextflux          # 停掉，端口才让给源码后端
```

**改后端期间先 `docker stop gist-nextflux`，别让它自己起来。**

## 浏览器自动化的坑（2026-09-16 补）

- **`ego-browser nodejs -e` 里，`page.evaluate` 内不要用 `async` 函数**：会被脚本解析器判成
  「await is only valid in async functions」（报错栈指向 ego 内部 `[eval1]:16691`），整个脚本退出。
  改用 **promise 链**（`page.evaluate(() => fetch(...).then(r => r.json()).then(d => ...))`）即可稳定执行。
- **别用 `el.scrollTop = N` 当「滚动」**：列表用的是内部滚动容器 + 虚拟化，摸错元素时 `scrollTop` 会立刻被重置为 0
  （表现为「滚了但未读数没变」）。要真实滚动就用 `cdp('Input.dispatchMouseEvent', { type: 'mouseWheel', x, y, deltaY })`。
- 想验证滚动已读这类行为，**优先写单元测试**（mock IntersectionObserver + fake timers），
  比在真实页面里量未读数可靠得多：见 `src/components/entry-list/useScrollMarkRead.test.ts`。

## HeroUI v3 的主题旋钮与圆角 token（2026-09-18 读 `@heroui/styles` 源码 + Theme Builder 实测）

**Theme Builder（https://heroui.com/en/themes）面板上只有 6 个旋钮**：Accent · Base · Font Family · Radius · Radius Form · Theme。
URL 上的 `lightness/chroma/hue` 三个参数就是 **Accent** 一项（例如 `?lightness=0.6678&chroma=0.2232&hue=36.66`）。

**圆角是两套变量**（这是最容易踩的点）：

- `--radius: .5rem` —— 组件基座（按钮、卡片、浮层…都读它）
- `--field-radius: calc(var(--radius) * 1.5)` —— **表单控件单独一套**，所以官方才有「Radius」和「Radius Form」两个旋钮
- 派生刻度：`--radius-xs` ×.25 · `-xl` ×1.5 · `-2xl` ×2 · `-3xl` ×3 · `-4xl` ×4
- 工具类：`.rounded-field { border-radius: var(--field-radius, calc(var(--radius) * 1.5)) }`

**所以「全局统一圆角」的正确做法**：把这两个变量写在 `<html>` 上，**所有读它们的组件一起变**，不需要逐个组件去改。
反面教训（本项目 12-18 就是这么做的）：只在 CSS 里覆盖具体 slot ——

```css
html[data-button-radius] [data-slot="button"] { border-radius: var(--ui-button-radius); }
```

这样**只影响 HeroUI 的 Button**（手搓按钮不跟），且 `--radius` / `--field-radius` 始终是出厂值，输入框 / 下拉 / 卡片 / 浮层一律不跟
—— 表面上有设置项，实际没统一。

**Button 的变体官方已现成**：`primary · secondary · tertiary · outline · ghost · danger`（`size` sm/md/lg；`isIconOnly`）。
「按钮长什么样」不要去自创一套填充/形状维度。


## 21 批（2026-09-18）：界面设置持久化 —— 设计取舍与踩过的坑

**8 条决策点（我推荐 / 用户全批）**：① 搬 `ui-settings` + 主题三键 + 语言 + 分类展开态，**不搬**自动刷新历史与图片尺寸缓存；② 尺寸类（列宽/缩放/侧栏）**按设备分套** desktop/mobile；③ 写前先 GET 再合并整包 PUT，不加乐观锁；④ localStorage 留作**本地缓存**（首屏不闪），服务端为准；⑤ 未登录/离线 → 写本地 + 脏标记，登录后补推；⑥ **700ms 防抖合批**，`resetToDefaults` 合成一次写；⑦ 导出/导入可读 JSON（设置 → 数据控制）；⑧ 键名 `gist-*` → `krss-*` **与发布改名合并做一次**。

**为什么后端只做 JSON 透传、不给 25+ 个设置字段建模**：本项目有前科 —— 后端 DTO 少一个字段，前端设置会**静默失效且不报错**。界面设置字段还会继续长，建模等于给自己埋雷。所以 `UISettings.UI` / `SidebarState` 是 `json.RawMessage`，后端只校验「是 JSON 对象 + 不超 256KB」，形状由前端约定（`{shared, device:{desktop, mobile}}`）。

**几个坑（都真踩过）**

- **`:8082` 上跑的旧 bundle 会冒充新代码**：验证第一轮时键名迁移「看起来没生效」（7 个键还叫 `gist-*`）—— 其实是 PWA service worker 拿上一次 `:8082` 的预缓存包在服务。修法：先 `navigator.serviceWorker.getRegistrations()` 全部 unregister + `caches.keys()` 逐个 `delete`，再 reload。**判断依据**：`performance.getEntriesByType("resource")` 里的 JS 文件名前后不一致（`app-I9RFwNeq.js` → `app-CxahJVth.js`）。
- **`vi.spyOn(window.localStorage, "setItem")` 在 jsdom 上根本不生效**：jsdom 的 `Storage` 是 Proxy 实现，给方法名赋值会被当成**存了一条数据**（值 `String()` 掉）—— 单文件跑（走 `setup-dom.ts` 的内存实现）数得出写入次数，**整仓跑就数出 0 次**，是最费时间的那种假绿。正解：临时换掉 `window.localStorage` 这个对象本身（`src/test/storage-write-spy.ts`）。
- **`mock.calls[0][0]` 在 `noUncheckedIndexedAccess` 下报 TS2532**：测试里取 mock 入参要收口成一个带断言的取值函数（`sentPayload()`），否则 `tsc -b` 红一片。
- **设备档的读时机**：`currentDeviceClass()` 看 `window.innerWidth`，同一台机器拉窄窗口就换档 —— 必须配 `matchMedia("(min-width: 768px)")` 的 change → `refreshDeviceScopedSettings()`，否则会出现「手机布局 + 桌面列宽」。
- **`resetToDefaults` 必须一次写完**：原实现在 25 个键上循环调 `setUISetting` = 25 次落盘 + 25 次同步（现在还有 25 次「已保存」toast 的风险）。
- **`index.html` 的首屏内联脚本要跟着改名**：它自己读 `localStorage` 定主题/语言，不改成新键优先 + 老键兜底，改名当天首屏会闪一下旧值（`pwa-metadata.test.ts` 已钉住两条路径）。
- **导出/导入的两条硬规矩**：凭证类（API Key / 代理密码 / Bark 地址 / `user.jwt_secret` / `user.password_hash` / RSSHub access key / anubis cookie）**不进文件**并在 `excludedKeys` 里列名；导入出现白名单外的键 → **400 且一条都不落库**（「导入了一半」是最难排查的形态）。

## 14 批（2026-09-18）：代理按来源生效（迁移 26）—— 设计取舍与踩过的坑

**取用顺序与「谁说了算」**：订阅 → 文件夹（含父级链）→ 全局，**第一个非 NULL 说了算**；某一层选了「走代理」时用哪套地址 = 这一层单独指定 → 否则全局那套。全局总开关关掉 = 全局那套不存在（`GetProxyURL()` 返回空），此时只有「单独指定」的层能走代理，其余一律直连；选了「走代理」却拿不到地址 → 实际直连并把原因写进行上的生效结果（`effective.missing`），不静默。

**刻意另开入口，不动 `GetProxyURL()`**：`service.ProxySourceService` + `pkg/network.SourceProxyProvider` + `ClientFactory.NewHTTPClientForFeed / NewAzureSessionForFeed`。解析器**每轮现读、零缓存**（11-20 的「每轮重读」规矩）—— 单测直接钉住「每次建客户端都要问一次解析器」。解析不出来（库里查不到）时才回落全局那份，老行为不变。

**四个「知道 feed 身份」的调用点**：抓取（`refresh_service`，含 Anubis 重试那条）、图标（`icon_service` 的下载/重试/backfill；**顺手把 backfill 里 gofeed 取图那次出网也改成按来源**，原来它绕过了 ClientFactory 直连）、正文（`readability_service` 的 azure session）、免费翻译（`ai_service`，由 entryID 反查 feedID）。图标那两个公开方法（`FetchAndSaveIcon/EnsureIcon`）保留原签名、内部转调 `*ForFeed(feedID=0)`，免得全仓 stub 一起改。

**两个坑（都真踩过）**

- **HeroUI `Modal` 套在 Radix 弹窗里 → 滚轮被 `react-remove-scroll` 吃掉（「页面不能滑动」的真根因）**：订阅编辑弹窗里点「管理覆盖…」开出来的面板，一开始用 HeroUI `Modal`（`Modal.Body`/普通 div 都试过），`clientHeight 649 / scrollHeight 4856` 明明是滚动容器，**滚轮就是不动**。取证方式：给 `Event.prototype.preventDefault` 打桩、把栈打出来 —— 调用者是 `node_modules/.vite/deps/Combination-*.js` 里的 `shouldPrevent`，也就是 **Radix `DialogContent` 的滚动锁 `react-remove-scroll`**：它在 `document` 上装了 wheel 监听，凡是**不在它 shard（那层设置弹窗自己的 DOM 子树）内**的事件一律 `preventDefault()`。HeroUI `Modal` 的内容被 portal 到 `document.body`，天生落在 shard 之外 ⇒ 吞掉。
  **正解**：壳换成**项目自己的 `@/components/ui/dialog`**（Radix，`SettingsModal`/`EditFeedDialog` 同一套），骨架照抄 `SettingsModal`：`DialogContent` 给固定高度（`h-[80vh] … overflow-hidden p-0`）→ `flex h-full min-h-0 flex-col` → 中间 `min-h-0 flex-1 overflow-y-auto` 才是真滚动容器。改完真机滚轮实测：0 → +400 → 400 → −400 → 0，同一次里 `preventDefault` 命中 **0 次**（改前每次都命中）。
  **同类病灶已一并修掉**：`src/components/automation/FilterMatchesDialog.tsx`（原来也是 HeroUI `Modal` + `Modal.Body max-h-[60vh] overflow-y-auto`，开在同一个设置弹窗里）已换回项目自己的 Dialog 同一套骨架；真机复验：矮视口（1400×420）下 `clientHeight 218 / scrollHeight 471`，滚轮 +150 → scrollTop 150、−150 → 0，`preventDefault` 命中 0 次。它 09-17 之所以改成 HeroUI，是为了躲「Missing Description or aria-describedby」那条控制台告警 —— 那个告警 `@/components/ui/dialog` 里已经用视觉隐藏的 `DialogDescription` 兜掉了，理由不再成立。
- **别再把「自动化滚轮不动」当成页面问题**：ego-browser 的 `page.mouse.wheel` 会**落后一拍**（`mouseWheel` 事件异步到达，读 `scrollTop` 得等 1–2 秒），早先据此误判成「这台机器上滚轮全都不产生滚动」。正解：先用 `Input.dispatchMouseEvent(pointermove)` 把指针放到容器上，再发一次 `mouseWheel`，**等 2 秒**读 `scrollTop`；判据是「两个方向都能动 + 同时刻 `preventDefault` 命中数」。

**脱敏**：订阅级/文件夹级的 `proxy_config` 里存明文密码（与全局那套一致），但**接口返回一律 `maskAPIKey` 掩码、日志只记「档位 + 有没有单独指定」**；PATCH 时把掩码值原样发回来 → 沿用库里那份（照 `setAPIKey`）。真机验证：UI 填 `pw-from-ui` → 库里 `pw-from-ui`、接口 `pw-***-ui`、日志里明文命中 0 次。

**前端缓存的顺手修**：覆盖是「就近生效」的（改文件夹，下面订阅全变），只靠 `invalidateQueries` 再拉一遍要等一两秒（91 行重渲染），用户会以为没生效 → 用 PATCH 回显的 `effective` 就地写进 query 缓存（`setQueryData`），点完 0.7s 内行上就变。
## 16 / 17 批（2026-09-18）：MCP 双向 —— 落地取舍与踩过的坑

方案见 `docs/MCP-方案-2026-09-18.md`。同一棵树里按 16 → 17 顺序做（共用一套协议底座 `internal/service/mcp`）。

**落地的关键取舍**

- **抓取分叉点**：`refresh_service` 把「saveEntries 之后的那一段」抽成 `saveAndPostProcess()`（去重 / FTS / 刷新结果记账 / 规则引擎 / siteURL 回填 / 图标），RSS 与 MCP 两条取数路径都汇到它。于是分叉真的在 `saveEntries()` **之前**，之后一行没改。MCP 分支只负责「连服务 → 调工具/读资源 → 按映射生成 `[]*gofeed.Item`」。
- **GUID = 去重键**：MCP 条目转成 `gofeed.Item` 时把映射键值塞进 `GUID` —— `computeEntryHash` 的第一级就是 GUID，于是 MCP 的去重顺序（键字段 → 链接 → 标题+时间）与 RSS **天然一致**，`saveEntries` 一行不改。键值也顺手成了界面要显示的「用了哪一级」。
- **没有链接字段的条目**：`saveEntries` 会跳过 URL 为空的条目，所以无链接时给一个**由去重键派生的稳定内部地址** `mcp://server/<id>/<hash16>` —— 既不丢条目，也不会重复入库（不这么做就是「静默出空」）。
- **`mcp_config` 里的 serverId 必须是字符串**：雪花 id 超过 2^53，这份 JSON 是原样透给前端的，用数字会在 JS 侧丢精度、订阅与连接对不上。为此给 `model.SnowflakeID` 写了 `MarshalJSON/UnmarshalJSON`（出字符串，入**同时兼容**老数字写法）。
- **构造函数变参加可选依赖**：`NewRefreshService(..., mcpService ...MCPService)` / `NewFeedService(..., mcpService ...MCPService)`。MCP 是可选依赖，这样 40+ 处既有调用点与测试一行不用改。
- **出向用长期 token 而不是登录 JWT**：token 明文只在生成那一次返回，库里只存 sha256；`/mcp` 端点挂在根路由（不挂 `/api` 的 JWT 组）。streamable-http 我们不提供服务端推流，`GET /mcp` 按规范回 **405 + Allow**。

**坑（都真踩过）**

- **`CountFeedsUsing` 一开始用字符串匹配 `"serverId":123`**：serverId 改成字符串后彻底失效 —— 实测「还有 2 条订阅在用」却删连接返回 **204**。改成真解析 JSON；解析时**必须 `decoder.UseNumber()`**：老写法的大整数解成 `float64` 会丢精度（1234567890123456789 → 1.2345678901234568e18），照样匹配不上。这个 bug 是**真机删连接时发现的**，单测 `TestMCPService_DeleteBlockedWhileInUse` 现在同时覆盖字符串/数字两种写法。
- **`db.Open(":memory:")` 在多连接下每条连接都是一个空库**：单测里「写进去、另一个查询读不到」的假失败就是它。测试一律用 `testutil.NewTestDB(t)`（共享缓存 + 唯一库名）。
- **`initialize` 的结果是 `{protocolVersion, capabilities, serverInfo:{name,version}}`**：一开始把 `ServerInfo` 写成顶层字段，于是 `hermes mcp add` 能连上、我们的客户端却拿不到服务名。按规范形状解。
- **取数会把 `tool_count` 刷成 0**：`markStatus` 原先在取数成功后也传 0/0 —— 现在沿用该连接上一次「测试连接」的计数。
- **MCP 调用走的是设置里的代理**：把测试用的假 MCP 停掉后，刷新报的是 `HTTP 502` 而不是 `connection refused` —— 这恰好证明了「出网一律走 `network.ClientFactory`（继承代理）」是生效的；错误同时落到该源 `error_message`、刷新结果 error、连接 `last_error` 三处，恢复后自动清空。
- **（已作废，2026-09-19 返工 16-10 支持了 SSE：自动识别 + 记住上次成功的传输）**原第一版不支持 `sse` 传输：建连接时 400 + 明确原因。当时不是静默降级，但返工后这条限制已删，`select.tsx` 的 disabled 注释与此处都只是历史记录。
