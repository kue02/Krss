# v1.1.3

2026-10-13 发布。自 [v1.1.2](https://github.com/kue02/Krss/releases/tag/v1.1.2)（2026-10-10）以来的 13 个提交。

## ✨ 新功能

- **品牌图标全套换代**。按品牌规范分档：**32px 以上用完整标志，24px 以下用仅字母版**（16px 时完整标志的信号弧会糊成一团）。侧栏 32px、登录页 64px 用完整版，设置侧栏 24px、浏览器标签页与书签用仅字母版；favicon（16/32/48）、apple-touch（180）、PWA（64/192/512）与 maskable 图标全部按各自安全区重做。
- **条目列表默认「只显示未读」**，并记住你上次选的那一档（切到「全部」后下次仍按「全部」打开）。

## 🐛 堵塞与翻译

- **免费翻译通道（有道 / Google）下界面被堵死**。翻译走的是长连接（SSE），而浏览器对同一站点**最多只给 6 条并发**。预载每条各占一条，加上打开正文那条和列表批次，正好顶满 —— 于是设置页打不开、其他条目一直转圈。现在预载不再自己拉流：改成让后端**后台把译文翻好落缓存、请求立刻返回**，你点开时直接命中缓存。另有全局闸门兜底（最多 2 条翻译流）。
  实测：滚列表时流式请求 **0 条**（改前 3 条并发），翻译期间设置接口 **24–96 ms**（改前最坏 45.6 秒）。
- **正文没翻译**。段落里只要带任何标记（`<b>` / `<a>` / `<ul>` / 图片），这块此前整块交给模型；模型不可达时这些块**全部失败且悄悄留原文** —— 表现就是「标题翻了、正文没翻」。现在改成**逐文本段翻译、标记原样保留**（链接地址、列表项、图片、代码块都不动，代码内容不翻）。分隔符被翻译器改写时会退化成整段包壳，不会退回「静默留原文」。
- **翻译失败会明说**。以前失败是静默的，现在会说「有 N 段没译出来」并带上真实原因。

## 🐛 其他修复

- **图片加载慢**。正文图片都要经服务端代理出网取，而代理**没有服务端缓存**（实测同一张图连取三遍 0.708 / 0.967 / 0.669 秒，一遍都不快）。现在加了磁盘缓存，**第二次起 0.001 秒级（约 900×）**；正文首屏 3 张图改为立刻加载（`fetchpriority=high`），预载相邻条目时会顺带把前几张图也预热。
- 社交视图：点正文里的链接不再连带跳进正文。
- 社交视图：有引文时，正文图片现在排在引文**前面**（按原帖顺序）。
- 自动化：带空格或跨标签的文本条件（例如 `🥰 #机场 #推广`）此前永远匹配不到，现在能命中（同时匹配原始 HTML 与去标签纯文本，老规则行为不变）。
- AI 设置：「测试 / 保存」挪到「已保存的提供商」区域；**翻译通道选免费翻译后也能保存**了（此前保存按钮被模型/密钥的门禁挡住）。
- 设置页左上角 logo 旁边不再漏出一行源码注释。

## 🔧 内部

- 新增 `POST /api/ai/translate/warm`（预载用：后台翻好落缓存、立刻返回 202/200；同条目去重，不重复翻）。
- 新增代理媒体磁盘缓存：`$KRSS_DATA_DIR/proxy-cache`，默认上限 **512MB**（环境变量 `KRSS_MEDIA_CACHE_MB` 可调），超了按最久未用淘汰；`<video>` 拖进度条的 Range 请求不缓存。
- 前端测试 **124 个测试文件 / 1135 个用例**全部通过；后端 15 个包全绿（含 `-race`），`golangci-lint` 0 问题。

## 升级

```bash
docker compose pull && docker compose up -d
```

本版**没有数据库结构变更**，升级不需要手工迁移。缓存目录会在首次请求图片时自动创建，请预留一些磁盘空间（上限默认 512MB，可调）。旧镜像标签建议留着做回滚保险。
