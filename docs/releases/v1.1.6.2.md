# v1.1.6.2

2026-11-01 发布。自 [v1.1.6.1](https://github.com/kue02/Krss/releases/tag/v1.1.6.1)（2026-10-21）以来的 2 个提交。

本版是 v1.1.6 之上的补丁版本（第 4 位递增）。

## ✨ 新功能

- **刷新拉下来新条目时，列表不再整块往下跳**。以前刷新一完成就把整段已加载列表按原来的位置重拉一遍，新条目一多，正在读的那张卡会被挤出已加载范围、直接从页面上消失，看到的效果就是列表整块移动一段后定住。现在只把新条目补到已加载列表的前面，原有卡片一张都不重建，插入带来的高度变化由浏览器在同一帧里补掉滚动位置。实测一次涌入 300 条新条目：正在读的那张卡从头到尾留在原位，滚动位置自动偏移 58537px（正好是 300 张卡的高度），没有跳动。
- **星标不再顺带标已读**。点星标、取消星标只改星标状态；已读状态、未读计数、列表位置都不受影响。
- **通知视图的折叠簇可以直接标已读**。时间线里折叠成一簇的卡片，簇标题上就有「标已读」，不用先展开再逐条标。
- **新增条数提示**。刷新结束会弹一条 3 秒的「新增 N 条新条目」，点它直接回到顶部看新内容，不点自动消失；列表本来就在顶部时直接插入，不弹提示。

## 🐛 Bug 修复

- **大窗口下文章列表的插入位移**。列表铺满整窗时改为整页滚动，新条目插入后不再出现位置漂移。
- **刷新完只有零星几条时会凭空挪一下**。补偿逻辑不再拿上一帧的旧坐标去猜位置，缺少锚点时宁可不补。

## 🎨 改进

- 全量刷新期间列表更稳：不再每刷完一个源就把整窗重拉一次，只做头部增量。

## 🔧 内部

- 刷新收尾统一走 `entries-head-sync`：从顶部翻页直到撞见已加载的条目，只把之前的条目并入第一页；翻到上限仍没撞见（列表被整体换掉）或列表为空时退回整窗重取。虚拟化文章列表因为行按位置绝对定位，维持整窗重取。
- 非虚拟列表交回浏览器原生 scroll anchoring，虚拟化文章列表保留 JS 锚点补偿。
- 前端 135 个测试文件 / 1215 个用例全过，`tsc -b` 0 错。

## 升级

```bash
cd /你的部署目录
docker compose pull
docker compose up -d
```

> 本版为四段版本号（1.1.6.2），镜像只推 `:latest` 与 `:1.1.6.2`，不会覆盖 `:1.1` / `:1` 这两个滚动 tag。回滚把 `IMAGE_TAG` 改回 `1.1.6.1` 再 `docker compose up -d` 即可。
