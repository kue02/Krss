# v1.1.6.1（2026-10-21）

第五十四批：社交媒体 / 通知视图的**列表级主动翻译** —— 不用点进正文，卡片上直接看到中文。

本版是 v1.1.6 之上的补丁版本（第四位递增），只有这一批功能，没有其他改动。

## ✨ 新功能

### 列表里直接读译文

- **社交视图卡片正文显示译文**：Twitter / Telegram 等社媒订阅的卡片正文，在自动翻译生效时直接替换为中文译文，折叠高度、图片画廊、引文顺序全部保持原样（只换文字来源）
- **通知视图卡片预览显示译文**：时间线卡片的折叠预览同样走译文，展开后的正文页本来就会翻，折叠与展开两处的文字现在一致
- **机器翻译标记**：卡片来源行右侧出现一个小语言图标（14×14，hover 提示「机器翻译」），只在「本条当前显示的正文是译文」时出现，方便一眼分辨哪些是译文

### 自己会翻，不等预载

- **列表主动翻译**：滚动到哪个条目就把哪个条目排进翻译队列，不再依赖「滚动预载恰好路过才翻」。打开视图后逐张卡片陆续变成译文，翻页新加载的条目也会自动进队列
- **限流保护**：同时在飞最多 6 条（并发档位 × 2），不会把免费翻译通道打爆
- **翻译通道只走批量通道**：列表里绝不发长连接的流式翻译请求（同源连接数有限，会把设置页和其他请求一起堵住）

### 标题也能翻了

- **标题 / 摘要逐字段判定**：以前是「这条要不要翻正文」，正文已经是中文就一票否决，英文标题跟着永远不翻（社交帖常见「中文正文 + 英文标题」）。现在标题按标题的语言、摘要按摘要的语言分别判定，任一外文就翻
- **免费翻译通道支持标题翻译**：只配了「翻译通道 = Google 免费」而没配模型时，标题批量翻译接口以前直接 500，而正文能翻 —— 于是「正文中文、标题永远英文」。现在与正文同口径，免费通道可用

## 🐛 Bug 修复

- **订阅级开了翻译、列表仍显示原文**：卡片读译文时只看全局开关，而取译文按订阅级挑候选，导致译文本已在内存却读不出来。读数门与取数门统一为「条目级 > 订阅级 > 全局」
- **社媒卡多出一行标题**（本批自己引入的回归，已修）：判断「标题就是正文开头」时误拿译文正文比原文标题，中英永远比不中 ⇒ 标题被当成另一句话多渲染一行。改为用源站原文比对，与译文无关
- **批量译文路由漏 `/api` 前缀**：请求 404 被静默 catch 吃掉，表现为「功能完全不生效、控制台一片安静」。已补前缀，并让批量读失败在开发模式下留痕

## 🎨 改进

- 自动翻译口径保持不变：仍是「全局开 → 所有订阅都翻」的三态（条目级 > 订阅级 > 全局），本版没有改动这个语义

## 🔧 内部

- 新增后端接口 `POST /api/ai/translations/batch`（只读缓存、零模型调用）
- 后端测试 23 个包全过；前端 133 个文件 / 1197 个用例全过，`tsc -b` 0 错

